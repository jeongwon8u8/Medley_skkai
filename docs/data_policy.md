# 데이터 보안·입력 누출 정책

이 저장소는 기본 Private이더라도 민감한 임상 데이터를 넣는 장소가 아닙니다.

## Git 제외 대상
- 환자/대상자 식별 가능한 EEG, 원시 EEG(.edf/.set/.fif 등), 임상 metadata/설문, 건강정보를 담은 CSV/Parquet/XLSX
- 데이터셋 저장본, 대형 모델 가중치(.pt/.pth/.ckpt/.safetensors), 로컬 캐시 및 .env/비밀 키
- 환자 단위 예측 결과를 포함한 파일, 내부 서버 주소/계정/credential

## 접근권한
- 기관·라이선스·IRB/윤리 요건에 따라 데이터 이용 승인과 보관 경로를 별도 관리한다.
- 가능한 경우 식별키를 외부 공개 코드와 분리하고 데이터 최소화·접근 권한 제한을 적용한다.
- 만약 실수로 push했다면 단순 파일 삭제만으로 이력이 제거되지 않는다. 팀 관리자·보안 담당자에게 즉시 보고하고 credential 회전/이력 정리 등을 정책에 따라 진행한다.

## Leakage review 체크리스트
- label을 정의한 변수(예: MoCA, MMSE, UPDRS)가 predictor에 들어갔는가?
- 임상정보가 예측 시점 이후에 수집되었는가?
- 검사 기록 유무가 사실상 질환 분류를 노출하는가?
- 같은 환자의 세그먼트/방문이 train/test에 중복되었는가?
- 전체 데이터로 normalization, feature selection, imputation을 fit했는가?
- 교란 시 임상정보 donor를 test label로 선택하는 설정이 본 실험과 분리되어 있는가? (교란 분석에서만 허용)

공개할 수 있는 **합성 더미 데이터**만 테스트에 사용합니다. 합성 데이터가 실제 환자 데이터와 혼동되지 않도록 표시합니다.
